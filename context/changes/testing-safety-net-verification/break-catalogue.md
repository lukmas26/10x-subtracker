## Findings worth keeping

- **Row 2.** With exact-match middleware, the anonymous edit page renders **200**. No data leaks (the anon client has no grants, so the page shows its load error), but the page is served. Only the new nested-path anonymous step catches this.
- **Rows 3–4.** With the in-handler check gone, the database still refuses the anonymous write (RPCs are revoked from anon). Only the response differs, so the exact-redirect assertion is what makes the break visible.
- **Row 10.** Under the pre-Phase-1 assertions (`Boolean(error)`), the failed-save check and the anon RPC check would have passed on `PGRST202`.
- **Cascades (rows 6, 7, 11).** One broken rule fails several later smoke steps, because the list stops rendering once rows or categories are inconsistent. The targeted step is always among them.
